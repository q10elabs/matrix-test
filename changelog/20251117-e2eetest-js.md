# E2EE Test Suite - Node.js/matrix-js-sdk Implementation

## Task Specification

Implement a Node.js variant of the E2EE (End-to-End Encryption) test programs in the `e2eetest-js` directory, using `matrix-js-sdk`. The existing implementation in Python (`e2etest/` directory) uses the `matrix-nio` library.

The test suite should include four programs:
1. **init** - Register two users and set up E2EE encryption keys
2. **setup** - Create an encrypted room and invite the second user
3. **send** - Log in as first user and send an encrypted message
4. **recv** - Log in as second user and receive/decrypt messages

Configuration should be persisted:
- `userconfig.json` - User credentials and device IDs
- `roomconfig.json` - Room details

## High-Level Decisions

1. **Framework**: Use Node.js with TypeScript for type safety and async/await patterns
2. **SDK**: Use matrix-js-sdk (available via yarn, with sources at ~/src/matrix-js-sdk)
3. **Entry Points**: Four separate executable scripts (init.ts, setup.ts, send.ts, recv.ts)
4. **Configuration**: JSON files for persistence (same structure as Python version)
5. **Logging**: Use console logging with timestamp and level formatting
6. **Crypto**: Leverage matrix-js-sdk's built-in crypto support (libolm)

## Architecture Overview

- Create `e2eetest-js/` directory at the project root
- Use npm/yarn for dependency management
- Configure TypeScript build
- Create utility modules for common functions (login, config loading, etc.)
- Implement each program as a separate executable

## Rationales and Alternatives

1. **TypeScript vs JavaScript**: TypeScript chosen for better type safety and IDE support when working with matrix-js-sdk
2. **Separate scripts vs monolithic**: Keeping separate entry points mirrors the Python implementation and keeps concerns isolated
3. **ESM vs CommonJS**: Used ESM with TypeScript for modern JavaScript practices
4. **Direct execution vs build step**: Used tsx for direct TypeScript execution, eliminating build overhead while maintaining type safety
5. **Client initialization**: matrix-js-sdk requires manual crypto initialization and key upload, which is implemented in the client utility module
6. **Event handling**: Implemented sync-based event processing (like Python) plus event callbacks for recv.ts

## Implementation Notes

- **Package.json scripts**: All four programs accessible via `yarn init`, `yarn setup`, `yarn send`, `yarn recv`
- **Crypto support**: matrix-js-sdk's crypto module (libolm) is initialized per client and requires explicit key upload
- **Configuration persistence**: JSON files used for inter-program communication (identical to Python version)
- **Error handling**: Comprehensive error logging with status indicators (✓, ✗, ⚠)
- **Type safety**: Full TypeScript types with proper async patterns throughout
- **Logging**: Timestamped, formatted logs matching Python implementation style
